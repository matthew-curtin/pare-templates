**Idempotency keys on publish.** `POST /v1/events` accepts an
`idempotency_key`. Publishing twice with the same key inside 24 hours
returns the original event instead of creating a second one.

Derive the key from the thing that happened — `in_8121-paid` — rather than
generating one at call time, which produces a fresh key on every retry and
therefore does nothing.

**Attempt bodies are captured.** Each attempt now records the first 2 KB
of the response body alongside the status code, visible in
`GET /v1/deliveries/{id}` and in the dashboard. When a subscriber says
they never received something, what their server said at the time is
usually the whole answer.

**`410 Gone` is terminal.** A receiver returning `410` marks the delivery
exhausted immediately rather than retrying six more times. Everything else
in the `4xx` range is still retried — a `404` is usually a deploy in
progress.

No breaking changes. Pinning to `2026-04-02` continues to work.
