**Secret rolling with a grace period.** Rotating an endpoint's signing
secret no longer means a moment where requests fail verification.

```bash
rookery endpoints roll-secret ep_9c4ktw02mn --grace 24h
```

During the grace period both secrets are computed and sent, comma
separated:

```http
Rookery-Signature: v1=4f7a1c…,v1=9b2e07…
```

**Accept the request if any value matches.** Client libraries at the
versions below already do. Hand-rolled verification that reads the header
as a single value needs a one-line change, and this is the reason the
header was defined as a comma-separated list from the start.

- `@rookery/node` 4.0.0
- `rookery` (Python) 3.6.0
- `rookery-go` 2.0.0
- `rookery` (Ruby) 3.0.0

**Endpoints are disabled after seven consecutive exhausted deliveries**,
rather than fifty. The account owner is emailed and nothing is deleted.
Fifty turned out to mean an endpoint that had been broken for two days was
still being attempted.
